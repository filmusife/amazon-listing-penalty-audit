# 报告结构

把完整报告写到 `outputs/{ASIN}-penalty-audit.md`。聊天里只放结论表和最高优先级粘贴块，避免用户“看不到文件又看不到内容”。

```markdown
# {ASIN} {站点} 7项隐性减分体检

## 结论
- 产品一句话、父体、变体表、公开排名/价格
- 7 项判定总表

## 执行顺序
Day 1 属性/A+ 数字（最安全）
Day 2 非英雄子体标题五点 + ST + ALT
Day 3 改图上打架的数字；不动合格主图

## 第 1–7 项
每项：判定、证据表、粘贴改法、为什么这样改能减静默扣分

## 按 ASIN 工单
每个子 ASIN：标题是否改、五点、属性、ALT 槽位表、ST
父体：通常不单独写文案

## 待用户补的实测
重量、外箱尺寸、铭牌功率、声级计、卡尺（若与主图标注不一致则以实测覆盖全文）

## 数据边界
哪些是前台实证，哪些是 DATA_MISSING
```

聊天最少要有：

1. 报告路径
2. 7 项判定表
3. 统一尺寸/属性粘贴块
4. ST 整段
5. 标题策略（哪几个改、哪个不动）
