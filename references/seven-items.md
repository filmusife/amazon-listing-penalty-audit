# 7 个核心减分项

先过 [amazon-policy.md](amazon-policy.md)，再按本文件打 1–7。品类特有的单位、机制词、尺码表读 [category-overlays.md](category-overlays.md) 匹配节。每项输出：判定、证据、思考、字段名代码块。思考要写清官方规则和权重原因；代码块只有原文。

判定只用 `通过` / `不通过` / `DATA_MISSING`。不要用某个历史 ASIN 的数字当通用阈值。

## 1. Size / Weight / Dimensions 不一致

**不通过，若出现任一：**

- 属性栏、A+、五点、包装、主图/尺码图标注，有两套及以上尺寸或容量
- 同一父体下不同子 ASIN 的非变体维度规格不同（主题是 Color，但尺寸/容量跟着颜色变）
- Item Weight 为空，且该类目筛选器常用重量
- Style / Material / Size 等字段是脏值（如 Style=`NICE`、Size=`Large` 却无对应测量）或各变体互相矛盾

**通过：** 应一致的规格逐字相同，重量已填或该类目不适用，材质/成分与可见实物一致。

**改法：** 给一套统一字段表。除变体维度外，全部子 ASIN 复制同一套值。尺寸优先用卡尺或图上标注；看起来更整的属性栏数字不能压过可测量证据。思考区说明：筛选器、COSMO 和 Rufus 都读这些属性，一套数能进精筛、能被引用，也能少 INAD。代码块里只放字段名和值。

## 2. 变体主题错配

**不通过：** 主题是 Color 但子体实际差的是尺寸/材质/容量/口味；或主题是 Size 实际只是颜色。

**主题通过、内容不通过：** 主题正确，但标题/五点/属性未对齐（旧文案和新文案并存、A 色写了 B 色、尺码名和测量对不上）。这时 **不要拆组**，对齐文案。分裂文案会让 COSMO 搞不清这组货到底卖什么。

**通过：** 主题 = 真实差异维度，且所有子体共用同一套标题模板和五点，只替换变体词。

英雄子体若标题 **已经合规** 且有稳定小类排名，不要为了“更完整”去改它的标题。该 ASIN 不要输出标题代码块，只在思考区写“不动”和原因。

英雄标题一旦违规（warranty、guaranteed、主观夸大、禁用符号、被截断或抑制），必须改，排名好也不能留。美国站重写默认 ≤75 字符，溢出进 Item highlights。

## 3. Browse node 多选或错选

**通过：** 前台面包屑叶子类目与产品类型一致，且该类目前列竞品是同类产品。

**不通过：** 叶子类目明显跑偏（成品挂到配件、错误部门、前列竞品完全不是同类）。

**DATA_MISSING：** 后台到底挂了几个节点。前台只能看到主路径。

**改法：** 主节点只留最精确的 1 个；最多再加 1 个真正相关的第二节点。删除无关节点。不要为了“多曝光”多挂。代码块只放建议的节点名。

## 4. 图片 ALT 空白、错语言或空泛

ALT 语言必须匹配 **该站点 Listing 语言**。美国站/英语站必须是英文；中文 ALT 在 US/UK/DE 一律不通过。日本站用日文，不要套用“必须英文”。

**不通过：** colorImages 无有效 altText；A+ 图 alt 为空/错语言/只有品类词（如 `coffee grinder`、`yoga mat`、`dress`）。图上若有 warranty / guarantee / certified 徽章，政策问题记到第 9 项，这里仍要给合规 ALT（描述产品，不复述徽章词）。

**改法：** 必须先看图再写 ALT。一句、站点语言、产品名 + 可见功能 + 材质或场景 + 变体词。不堆词，不用竞品品牌和夸大词。

必须同时产出两块，缺一不可（完整清单进报告文件）：

- 图库 ALT：按 **每个 ASIN 的槽位实图** 写 MAIN / IMG2 / IMG3…
- A+ ALT：每个已分析的 A+ 图都要有，编号 A+1、A+2…（模块从上到下，图从左到右）

主图合格就不要重拍主图。ALT 跟当前仍在线的画面；若思考区要求换图，换图后的 ALT 另开一个代码块，块内仍然只有目标语言句子。

## 5. Search Terms 竞品品牌 / ASIN

前台标题五点没有品牌词 ≠ 后台 ST 干净。ST 读不到就整段替换。

**ST 只放：** 前台未出现的同义词、次场景、原料/材质长尾、操作或用途同义词。

**ST 禁止：** 竞品品牌、任何 ASIN、标题/五点已有词、夸大词、warranty、与实物不符的品类/机制词。机制词是否属实看品类 overlay，不要把厨房电器的机制词套到服装。

美国站 <250 字节，空格分隔，全小写。同一父体通常共用一段 ST（变体词已在标题末尾）。代码块里只有那一行小写词，字节数写在思考区。用 [../scripts/scan_listing.py](../scripts/scan_listing.py) 核字节，不要目测。

## 6. 描述 / 图片 vs 实物

**高风险 / 不通过：** 图与文数字打架（容量、件数、功率、分贝、尺码、成分百分比、兼容型号）；尺寸图/尺码表和属性栏不是同一套数。

**改法：** 选一个可测量口径，所有位置一起改。营销口径（“可用次数”、虚高容量、理想尺码）让位于克数、英寸、实测表。没有第三方报告时，性能数字用更保守的那套，并写清测试口径。配件图不要标 GIVE AWAY / Gift 除非真是标配。图上也不要 warranty 徽章。

未实测的重量/功率/实验室指标就不要填。换图指令写在思考区，不要写进五点/ALT 代码块。

## 7. 30 天 list price 改价超过 5 次

Amazon 惩罚的是卖家反复改 **list price** 刷权重，不是参加 Lightning Deal / 秒杀 / 7-day deal / coupon。

**判定流程（必须按顺序）：**

1. 打开 Keepa（或同类）价格图，同时看 Amazon / Marketplace New / List Price / Lightning Deal / Coupon 图层。
2. 给每个拐点分类：
   - **促销，不计次：** 有 Lightning Deal、7-day deal、Best Deal、coupon 标记；或 List Price 水平线不动、Buy Box 下跌后 1–7 天回到原位（V 型）。
   - **真实改价，计次：** List Price 台阶式移动并在新价停留超过 7 天；或无促销标记、Amazon 价与 List Price 同步改到新平台价。
3. 只统计真实改价。近 30 天真实改价 >5 次 = 不通过。
4. 促销造成的锯齿 = **通过**。思考区可写“有秒杀/券，不是 list price 抖动”。
5. 只有 Buy Box 曲线、看不见 List Price 和 Lightning 标记 = `DATA_MISSING`。不要判不通过。
6. 已经在做秒杀/券的 listing：即使通过或 DATA_MISSING，也 **禁止** 写“锁死价格、停活动、改用 coupon 替代秒杀”。

**改法（仅当不通过）：** 代码块只放建议的稳定 list price 数字（沿用当前成交口径）。coupon / Lightning Deal 怎么做，写在思考区。不要为划线价把基础价抬上去再降下来。同一父体子体供货价保持一致，除非变体本身就是不同规格定价。
